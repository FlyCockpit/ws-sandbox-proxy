# Web shell rules

## Shell rules

Four rules every page meets, in both themes and at every width. `pnpm policy:checks` enforces what a static check can (rules G8 and G9 in `scripts/check-web-conventions.ts`, gate 4 of `scripts/check-agent-rules.ts`), `apps/web/src/components/public-shell.test.tsx` and `apps/web/src/lib/theme-contrast.test.ts` pin the markup and the tokens, and `pnpm check:layout` measures the geometry in a browser (§ Layout check).

1. **A footer sits at the bottom of a short page.** wssp has no site footer today: the landing is the only public page, and the app shell has the BottomNav on phones. The public shell (`apps/web/src/components/public-shell.tsx`, used by the `_public` layout and the 404) already lays its `<main>` out as one `flex min-h-full flex-col` column whose routed page grows (`flex-1`), so a footer added later goes once, as that column's last box: on a short page its bottom is then the scroller's bottom, on a long page it follows the content. No `position: fixed` footer, no `min-h-svh` layout, no second scroller, and no `<footer>` in a route file (a `<footer>` inside an `<article>`, `<section>` or similar sectioning element is that element's own and stays). A page that should fill the remaining height (a centred empty state, the 404) uses `flex-1`.
2. **Full-bleed dividers span the viewport.** The headers' `<hr>`, the admin section nav's `border-b` and full-width banners (the 2FA banner) reach the viewport's right edge at every width, from the start of their column: 0, or the dashboard content column's left edge next to the desktop sidebar. On a page that scrolls, rules inside `<main>` meet its visible scrollbar, which sits at that edge, as on any scrolling page. That is why neither `<main>` reserves a scrollbar gutter: with classic scrollbars (Windows, Linux) a stable gutter is an empty 15px strip that every rule inside the scroller stops short of, even when nothing scrolls. The cost is that centred content moves by half a scrollbar when a page grows past the viewport on those platforms; overlays don't cause it, because the overlay scroll locks (Base UI, vaul) lock the document, not `<main>`, and nothing toggles `overflow-y` on `<main>`. A bounded nested pane (a terminal, a table) may still reserve its own gutter.
3. **No surface ignores the theme.** The theme is the stored choice, else the OS, applied as the `.dark` class before first paint (`packages/config/src/theme-init.ts`). Every surface (toasts, banners, popovers, menus) uses the tokens in `packages/ui/src/styles/globals.css` and `dark:` variants, never a `prefers-color-scheme` query or a literal colour; a new colour becomes a token there. A colour that is deliberately not a theme colour (a QR code, a mask, a colour derived from `currentColor`) carries a `theme-exempt: <reason>` comment on its line or the line above, as the vendored `packages/ui/src/styles/shadcn-tailwind.css` masks do; `url(#id)` references are not colours. Toasts are a popover surface: `globals.css` fills sileo's pill with `--popover`, writes the title in `--popover-foreground` and maps sileo's state colours to `--state-*`, `--destructive` and `--primary`, and the Toaster (`packages/ui/src/components/sileo.tsx`) gets no `theme` prop (sileo's themes invert the page). Text and state colours reach 4.5:1 on the surface they sit on in both themes.
4. **Every route renders inside a shell, the 404 included.** An unknown URL matches no layout, so `$lang`'s `notFoundComponent` (`PublicNotFoundPage`) wraps the not-found body (`components/not-found-page.tsx`) in the public shell: header with language and theme controls, scroller. A `notFound()` thrown by a route without its own `notFoundComponent` lands on the same public 404, which is how hidden admin pages answer (`lib/hidden-admin.ts`): an app-shell 404 for `/admin` next to a public-shell 404 for an unknown URL would reveal that `/admin` exists.

## Layout check

`pnpm check:layout --url <web dev server>` (`scripts/check-layout.ts`) opens the landing page, the 404 and the sign-in page at 390×844, 1280×800, 1440×1600 and 390×300 in agent-browser's headless Chromium, which draws classic scrollbars, and fails when the document scrolls, a page is outside a shell, `<main>` reserves a gutter, or a full-width rule stops short of its edge. It also raises the file-drop toast with the stored theme light, then dark (the OS set to the other one), and fails when the toast is not filled with that theme's `--popover` or its title, badge or action is below 4.5:1. With `--login <email>` and the password in `CHECK_LAYOUT_PASSWORD` (an account with a second factor also needs a current code in `CHECK_LAYOUT_TOTP`), it adds the dashboard (2FA banner) and the admin users page (sticky section nav). It needs a running `pnpm dev` (web and server) and agent-browser on the PATH, so it is not part of CI; `pnpm check:layout:test` (in `verify:tooling`) covers its judge.
